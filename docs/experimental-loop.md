# Experimental loop toward native reconstruction

The target is a native adaptation preserving an approved experience, not a convincing sequence of unrelated images. A generated scene may vary only where its contract permits. Unique authored content, persistent facts and delayed consequences must retain their information somewhere in the ROM or state.

## Loop and decision rules

1. Freeze a contract, corpus, train/test split, hardware budgets and failure criteria before fitting. Record observations, inference and authored choices separately. Keep a deliberately hostile control.
2. Find the cheapest experiment that could invalidate the next claim. Start with host rejection tests; advance survivors to the exact native ROM. Include complete decoder/model/index bytes, peak memory and worst-case latency. Compare with the strongest implemented conventional baseline.
3. Preserve the first failure. Change one cause at a time; rerun the affected check and keep comparable artifacts. Never replace a failed fidelity result with a plausible screenshot or an uncounted repair implementation.
4. Select from the measured size/latency frontier. A learned representation earns its place only by improving the complete outcome. A negative result redirects the architecture; it does not justify lowering fidelity silently.
5. Increase one source of difficulty: unseen combinations, unique content, delayed dependencies, realistic workloads, then a different input architecture. Measure adapter code and human decisions separately. Synthetic transfer is never cross-game generalization.

## Ordered uncertainties

| Question | Disproof experiment | Advance criterion |
|---|---|---|
| Can token generation execute natively? | Frozen tiny predictor versus procedural code | Completed: native execution works; learned size/speed advantage fails |
| Can authored scenes share information without inventing details? | Frozen learned patch dictionary versus raw, bit packing, RLE and LZ back references; unseen motifs and entropy controls | Exact reconstruction, full native accounting; report failure/expansion per domain |
| Can full scenes arrive comfortably? | Measure decoding separately from VRAM transfer, retain all input-to-visible frames | At most four emulator frames for full regeneration, two for ordinary movement; no hidden LCD blanking |
| Can state abstraction preserve delayed influence? | Counterfactual traces with visually identical present states and differing later outcomes | Distinguishable consequences remain distinguishable; no screen-only state merging |
| Does this recover a real game's behavior? | Local source-data parser plus recorded original behavior on a dependency-complete slice | Differential behavior and explicit approved departures; independent replay |
| Does the representation transfer? | Freeze runtime and adapter interface before unfamiliar input | Report new code, manual specification and failure separately |
| Does it work on the target? | Exact cartridge ROM and physical Chromatic play/measurement | Identified hardware, captured inputs/results, usability evidence |

## Architecture under test

An exact causal state kernel drives a compact scene description. Content codecs reconstruct authored material; bounded rendering exposes facts and choices. Learned proposals may help offline analysis/search or encode reusable motifs, but must not invent canonical quest facts. An exact escape path for novel content counts toward every size claim. A validator that contains the complete answer is an implementation, not free assurance.

The immediate experiment uses original synthetic visual content and the existing native room/state kernel. It can settle codec costs and a rendering bottleneck, not BG3 feasibility. No user-machine intake is needed. The current missing evidence is real-game rules/content/dependency recovery, not another installation-header scan. Further user effort should wait for a single bounded collector whose outputs answer a specified hypothesis.

## Stop and rejection conditions

- Reject a codec for a domain on any mismatch, unbounded decode, hidden repair data or an undeclared factual change.
- Reject a performance claim when decoder time alone passes but visible output misses its budget.
- Reject a compression claim based only on weights or a naive uncompressed baseline.
- Treat capacity overflow, unknown semantics and missing permissions as explicit unresolved/rejected outcomes.
- Retain failed approaches. Do not keep increasing synthetic scale to suggest that a commercial game has been adapted.
